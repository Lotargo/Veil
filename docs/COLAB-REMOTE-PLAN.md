# Colab как удалённый GPU для VEIL — план и состояние работ

> **Статус (2026-10-13, вечер):** этапы 0–3 сделаны: шов `InferenceBackend`, мост WSL и вход, вкладка Remote GPU, воркер на VM, менеджер runtime и Create на Colab (переключатель This PC / Colab). Воркер проверен на G4 во всех режимах Create (раздел 2.5). Ключ Civitai теперь вводится в Integrations › Model sources и хранится в системном хранилище учётных данных (4.9). Дальше — сквозной прогон через API VEIL на модели Moody, потом этап 4.
>
> Начинай новую сессию по удалённому GPU отсюда. Документ собирает решения пользователя, замеры, правила Colab, архитектуру и чек-листы этапов.

## 1. Решения пользователя

- **Colab работает как облачный инференс** (по образцу RunPod serverless / Replicate): воркер на VM без состояния выполняет любой воркфлоу ComfyUI из самодостаточного задания, отдаёт результат и удаляет у себя входы и выходы. Colab — просто арендованная машина с GPU.
- **Google Drive необязателен.** Тетрадь воркера VEIL передаёт через CLI (`colab exec -f` читает файл локально), модели каждая VM качает по прямым ссылкам с проверкой sha256.
- **Аккаунт — тот, под которым пользователь вошёл в Colab CLI локально.** Пользователь ставит CLI кнопкой в интерфейсе VEIL, там же входит своим Google-аккаунтом. VEIL не читает и не хранит токен.
- **Отдельная вкладка** со статистикой: баланс CU, расход, активные VM, история сессий.
- **GPU по умолчанию — G4** (RTX PRO 6000 Blackwell): в 6 раз быстрее L4 при той же цене картинки. L4 — экономный вариант.
- **Автовыключение по простою настраивается от 2 до 60 минут** (по умолчанию 10). Тот же порог действует и в VEIL (`colab stop`), и на самой VM (сторож, 4.7).
- **Публичных туннелей нет.** «URL инференса» — локальный адрес внутри VEIL; ComfyUI на VM слушает только 127.0.0.1.

## 2. Что проверено (2026-10-13)

Аккаунт пользователя (Google AI Pro), баланс 350,96 CU, colab CLI 0.7.4 через WSL.

### 2.1 CLI через WSL

| Операция | Время |
|---|---|
| `colab new` (CPU) | 13,5 с; GPU — 6–10 с до READY |
| `colab exec` маленького скрипта | 4,6–8,2 с |
| Первая строка вывода `exec` | ~4 с, дальше строки идут **в реальном времени** |
| `colab upload` маленького файла **пока ядро занято** | 2,5 с, работающий цикл видит файл |
| `colab download` PNG 1,3 МБ | 3–4 с |
| `colab sessions` | ~9 с (включая проверку обновлений) |

- Каждый вызов CLI стоит секунды, поэтому вызов на каждый HTTP-запрос ComfyUI не годится: нужен один долгий `exec` и файлы.
- `google.colab.runtime.unassign()` из CLI-сессии освобождает VM — VM может выключить себя сама.
- Вход: CLI несёт свой публичный OAuth-клиент (`colab_cli/oauth_config.json`); поток «скопируй код»: ссылка печатается в stderr, код читается `input()` из stdin. Токен — `~/.config/colab-cli/token.json` внутри WSL. `colab whoami` (скрытая команда) показывает email, срок токена и scopes; `colab usage` — баланс, расход в час и число активных VM.

### 2.4 Найденные грабли

Найдено в живых прогонах воркера и уже учтено в коде:

- ComfyUI принимает свой `prompt_id` только в виде канонического UUID (строчными, с дефисами); воркер проверяет это при разборе задания.
- Jupyter отвечает на загрузку, перечитывая сохранённый файл; маркер, который воркер успел забрать, превращается в 404 у VEIL. Воркер берёт маркеры (`cancel`, `collected`, `settings.json`, `detach`) только через 1 с после записи.
- Jupyter-сервер VM иногда отвечает на GET ядра дольше 10 с (дважды за день: на L4 и на G4), и клиент CLI уходит в повторы дольше нашего таймаута. Клиенту ядра дано 30 с (`REQUEST_TIMEOUT`), `exec_code` повторяет зависшее подключение; все наши вызовы идемпотентны.
- Ядро выполняет одну ячейку за раз: после обрыва CLI старый `attach` держал бы ядро до конца окна. VEIL загружает `detach`, старый `attach` выходит, новый продолжает с последнего `seq`.

- У `colab exec` **таймаут 30 с по умолчанию** (`--timeout`): на L4 генерации прошли, но CLI упал «Timeout waiting for reply», а следующий `exec` один раз не дождался ответа ядра (read timeout 10 с). Долгим вызовам — явный `--timeout`, клиенту — повторы.
- `huggingface_hub` без токена на VM ~10 с ищет `HF_TOKEN` в хранилище секретов Colab: ставить `HF_HUB_DISABLE_IMPLICIT_TOKEN=1`. Ставить `hf_xet`.
- `colab update --install` через шлюз `remote-compute` падает: внутри нет `~/.local/bin` в PATH, не находится `uv`. Свой мост VEIL запускает команды через login-shell (`bash -lc`).
- Civitai: прямая ссылка Moody v40 без токена отвечает **401**; ссылка LoRA Identity Edit без токена даёт **307** на подписанный `b2.civitai.com`.

## 3. Правила Colab и как схема их учитывает

По [FAQ Colab](https://research.google.com/colaboratory/faq.html) (2026-10-13):

- На всех тарифах запрещены веб-сервисы, не связанные с интерактивными вычислениями, удалённые прокси, несколько аккаунтов для обхода лимитов и дипфейки.
- На бесплатном тарифе (и на платном с нулевым балансом) ещё запрещены SSH и работа в основном через web UI в обход ноутбука; такие среды для генерации контента часто прерываются.

Схема: только официальный CLI (`exec`, `upload`, `download`), без туннелей, без web UI и без SSH; ComfyUI не виден снаружи. Профили «лицо / замена / донор» на фото реальных людей попадают под запрет дипфейков на любом тарифе (раздел 6).

## 4. Архитектура

### 4.1 Общая схема

```
VEIL (Windows)                                     Colab VM (G4)
Create ─ InferenceBackend ─┬─ LocalComfyUI (http://127.0.0.1:8188, как сейчас)
                           └─ ColabBackend
                                ColabComfyUIClient
                                  │ colab upload ─────────▶ /content/mediastudio/inbox/<job>.json, inputs/
                                  │ colab exec (attach) ◀── /content/mediastudio/events.jsonl ◀─ поток воркера
                                  │ colab download ◀─────── /content/mediastudio/outbox/<job>/*.png
                                ProgressMonitor.handle()        │ POST 127.0.0.1:8188/prompt, /ws
                                                                 ComfyUI (headless)
```

### 4.2 Контракт `InferenceBackend`

Шов в `simple_routes.py` вместо прямых `_client()`, `ensure_comfyui_online()` и `_progress_monitor()`:

- `client` — объект с интерфейсом `ComfyUIClient`, который нужен Create и `WorkflowExecutionService`: `queue_prompt`, `upload_image`, `get_job`, `download_output`, `cancel_prompt`;
- `ensure_ready(timeout)` — локально: поднять ComfyUI Desktop (как сейчас); Colab: не блокировать, задание ждёт в очереди, пока VM стартует;
- `monitor` — `ProgressMonitor` (локально — по WebSocket; для Colab — без сокета, события приходят через `handle()`);
- `profile_health(profile)` — локально: модели и ноды на диске; Colab: вход в CLI и состояние VM (ресурсы приезжают с заданием).

`WorkflowExecutionService` уже импортирует результат через `client.download_output()` в библиотеку, папка output ComfyUI для этого не нужна.

### 4.3 Мост WSL и обёртка CLI (`app/remote/`)

- `wsl.py`: есть ли WSL и дистрибутив (`wsl.exe -l -q`), запуск `bash -lc` без окна консоли, построчный вывод, перевод путей через `wslpath`. Не зависит от `remote-compute` и Node.
- `colab_cli.py`: версия и обновление (`uv tool install -U google-colab-cli`), установка `uv` (официальный скрипт astral.sh) и CLI, `whoami`, `usage`, `sessions`, `status`, `new`, `stop`, `exec` с потоком и `--timeout`, `upload`, `download`. Всегда `--auth oauth2` и свой `--config` (`~/.config/mediastudio-colab/sessions.json`), чтобы не трогать ручные сессии пользователя. Токен общий с CLI пользователя.
- Без WSL: кнопка запускает `wsl --install` с повышением прав; UAC и перезагрузку пользователь делает сам.

### 4.4 Воркер на VM

Один самодостаточный файл `app/remote/colab/worker.py` (stdlib + `aiohttp` из зависимостей ComfyUI), отправляется через `colab exec -f`. Определяет в ядре функции и запускает фоновый поток:

- **bootstrap(spec)**: ComfyUI на закреплённом коммите, `uv pip install --system -r requirements.txt`, `hf_xet`, ноды из спецификации (архив коммита + sha256 файла-проверки), запуск ComfyUI на 127.0.0.1:8188. Этапы пишутся в журнал событий.
- **Поток реле**: следит за `/content/mediastudio/inbox/`; для задания докачивает недостающие ресурсы (URL + sha256, прогресс в журнал), кладёт входы в `input/mediastudio/`, ставит промпт с `client_id` воркера, слушает `/ws` ComfyUI и пишет события как есть; по завершении берёт `/history/<id>`, переносит файлы в `outbox/<job>/` и пишет `job_done`. Отмена: файл `cancel-<job>.json` → снять из очереди или `/interrupt`. Подтверждение `collected-<job>.json` → удалить outbox и входы задания.
- **Журнал** `/content/mediastudio/events.jsonl`: строки JSON с `seq`, `t`, `ev` (`boot`, `download`, `comfy`, `job_queued`, `job_done`, `job_failed`, `job_cancelled`, `idle_stop`, `error`).
- **attach(after_seq, max_seconds)**: VEIL вызывает его долгим `exec` (`--timeout` = max_seconds + запас); печатает события после `after_seq` и возвращается через max_seconds; VEIL переподключается с последнего `seq`. Обрыв CLI ничего не теряет: поток реле работает в ядре независимо от `exec`.
- **Сторож**: нет заданий, загрузок и подготовки дольше порога простоя + 2 минуты → событие `idle_stop` и `runtime.unassign()`. Страхует от упавшего VEIL, уснувшего компьютера и сети.

### 4.5 Задание

```json
{
  "id": "<prompt_id>",
  "client_id": "...",
  "workflow": { "...": "ComfyUI API JSON" },
  "extra_data": { "extra_pnginfo": { "...": "..." } },
  "inputs": ["mediastudio/mediastudio_source_<uuid>.png"],
  "resources": [
    {"folder": "diffusion_models", "filename": "moodyKrea2Mix_v40.safetensors",
     "sha256": "12d42c1f…", "url": "<прямая или подписанная ссылка>"}
  ]
}
```

`prompt_id` задаёт VEIL (ComfyUI принимает свой `prompt_id`), поэтому записи ранов создаются сразу.

### 4.6 `ColabComfyUIClient` и Create

- `upload_image` → `colab upload` во `inbox/inputs/`, возвращает имя для `LoadImage`.
- `queue_prompt` → задание в локальную очередь; диспетчер отправляет его, как только воркер готов (VM может ещё стартовать).
- `get_job` → состояние из локального зеркала в форме ответа `ComfyUIClient.get_job`; `completed` только после того, как файлы скачаны.
- `download_output` → байты из локального кэша скачанных файлов.
- `cancel_prompt` → файл отмены.
- Живой прогресс: события `comfy` из журнала идут в `ProgressMonitor.handle()`; пока VM стартует, `GET /api/simple/runs/<id>` показывает этап подготовки (выделение, установка, загрузка весов с процентом, запуск).

### 4.7 Жизненный цикл VM и автовыключение

Состояния: `unavailable` (нет WSL/CLI) → `signed_out` → `off` → `allocating` → `booting` → `ready` ⇄ `busy` → `stopping` → `off`; `error` с причиной.

- Порог простоя `idle_minutes` 2–60 (по умолчанию 10). VEIL: после последнего задания и без очереди → `colab stop`. VM: сторож через порог + 2 минуты.
- Закрытие VEIL → `colab stop` (best effort); жёсткое падение → сторож VM.
- Запуск VEIL: `colab sessions` со своим `--config`; найденная VM с живым воркером → переподключиться с последнего `seq`, иначе остановить.
- Отказ GPU (400 «нет квоты») → понятная ошибка и предложение другого GPU; отказанные GPU запоминаются для аккаунта.

### 4.8 Вход и выход

- Кнопка «Войти через Google»: VEIL запускает CLI, читает ссылку из stderr, открывает её в браузере и показывает поле для кода; код уходит в stdin процесса CLI и нигде не сохраняется.
- Выход: удалить `~/.config/colab-cli/token.json` в WSL — с предупреждением, что это выход и для CLI вне VEIL.

### 4.9 Модели и токен Civitai

- Ссылки берутся из `resources.json` профиля; Hugging Face — без токена.
- Ссылки Civitai VEIL разрешает **у себя**: запрос с токеном пользователя без загрузки, из ответа 307 берётся подписанная временная ссылка `b2.civitai.com`, и на VM уходит только она. **Токен не покидает компьютер.**
- Ключ вводится в Integrations › Model sources (`app/model_sources/`, `model-sources.js`) или в настройках ComfyUI в Create. Хранится в системном хранилище учётных данных (keyring, как ключи провайдеров); `config.json` — только запасной вариант без хранилища, старый ключ оттуда переезжает в хранилище при первом чтении. При сохранении VEIL проверяет ключ у Civitai (`GET /api/v1/me`): отклонённый не сохраняется. Сброс к заводским удаляет и его.

### 4.10 Вкладка Remote GPU (Integrations)

Новая группа «Compute» в навигации Integrations:

- установка и обновление CLI, вход и выход, email аккаунта;
- баланс и расход CU (`colab usage`, кэш 60 с), активные VM;
- выбор GPU (G4 по умолчанию, L4, A100, T4) и порог простоя 2–60 минут;
- текущая сессия: GPU, время работы, состояние, отсчёт до автовыключения, картинок, средняя скорость, примерный расход CU (тариф × время — баланс обновляется с задержкой);
- история сессий в SQLite (`remote_sessions`: GPU, тариф, старт, готовность, стоп, причина стопа, картинок).

### 4.11 Приватность

- VEIL не читает токен Colab; токен Civitai не уходит на VM.
- Промпты и картинки едут файлами, а не кодом `exec`, поэтому не попадают в локальную историю `colab log`.
- Входы и выходы удаляются на VM после скачивания; результаты живут только в локальной библиотеке.

## 6. Открытые вопросы

- **Задержка CLI.** Каждый вызов CLI стоит 2–8 с (запуск Python и авторизация в WSL); при больших пакетах можно держать постоянный процесс-мост внутри WSL с прогретыми сессиями HTTP.

- **Профили «лицо / замена / донор»** на Colab: предложена настройка «где запускать: локально или Colab», по умолчанию локально (запрет дипфейков Colab на всех тарифах). Ждёт решения пользователя.
- **Бесплатный тариф** не проверен: доступен ли T4 и хватит ли ~12,7 ГБ RAM для модели 12 ГБ.
- **Простой ядра:** при ограничении живости по активности ядра в CLI 0.7.x неизвестно, держит ли VM фоновый поток без выполняющейся ячейки; attach почти всегда держит ячейку занятой, но это надо проверить.
- **Обновление ComfyUI на VM:** коммит закреплён; когда и как его поднимать.


## Постоянный кэш моделей в Google Drive

В Integrations → Remote GPU добавлена опция **Keep model weights in Google Drive**. Она выключена по умолчанию и применяется к новой Colab VM. Существующая VM при изменении настройки не перезапускается.

При запуске VM подключается Drive через официальный `colab drivemount`. Если Google запросит доступ, интерфейс покажет ссылку и кнопку подтверждения после согласия. Без успешного подключения включённый кэш не подменяется временной папкой.

Полные веса сохраняются в `My Drive/VEIL/model-cache`. Новая VM копирует их на свой локальный диск и проверяет SHA-256; при отсутствии или повреждении кэша скачивает модель с исходного сервера и обновляет кэш. Запись выполняется через временные файлы и атомарную замену. Ошибка записи в Drive не удаляет корректную локальную модель, а отображается как предупреждение. Кэш занимает квоту Drive; автоматического удаления старых моделей нет.

Функция требует Colab CLI с командой `drivemount` (проверена по исходникам установленной версии 0.7.5). Тесты используют временные каталоги и локальные подставные процессы. В реальной новой Colab VM проверено восстановление четырёх файлов (19,1 ГБ) из Drive без скачивания весов с исходных сайтов. Windows/WSL-подключение требует отдельной ручной проверки.

При подключении новой VM Google обычно запрашивает разрешение повторно; постоянный кэш не является постоянным разрешением монтирования. Первичное сохранение весов в Drive завершается до постановки генерации в очередь и может заметно задержать первый запуск.
